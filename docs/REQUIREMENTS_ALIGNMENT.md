# 需求基线与实现核查（2026-09-08）

本文件根据本次用户描述整理产品目标，并记录重组前对源码和 reference 的首轮检查。后续重组的实际结构、已实现能力及限制见 [ARCHITECTURE.md](ARCHITECTURE.md)；下方核查条目保留为历史基线。与旧 PLAN 冲突时，以本次需求为准。下文明确区分目标、实现建议和已有实现；列出目标不代表功能已经完成。

## 1. 产品定位与主流程

以多种媒体为输入、以课程为组织单元、以每节课的讲义和笔记文档为中心，由 Agent 调用 Skills 完成资料获取、分类、理解、选材和内容生成的智能化自动化学习平台。

主流程：

```text
pku3b 获取课程 → 建立/更新课程空间
  ├─ 教学网课件、录播等资料同步
  └─ 拖入教材、额外教材、课件及其他学习资料
                    ↓
               按每节课组织
                    ↓
          录播转写 → 本节实际授课大纲
                    ↓
     依据大纲定位教材章节、课件页和相关资料片段
                    ↓
       选取、截取、整合 → 本节讲义/笔记文档
                    ↓
          阅读、修改、补充资料后再次生成
```

课程是基本组织单元，应从 pku3b 获取并建立稳定远端映射；手工创建可作为补充入口。课程内以实际授课节次组织学习文档。教材属于课程资料库，可服务多节课；一份课件也可以跨多节课使用。

录播决定本节实际讲了什么、顺序和边界。先得到独立可查看的大纲，再根据大纲选材。讲义需要整合定义、推导、例题、图表和课堂补充，保留必要上下文。额外教材用于补充相关内容，不能让未讲到的整章内容自动混入本节范围。

“选取/截断”首先解释为选择原资料中的相关页、段落、图表及时间区间，并整理成可读文档；原 PDF 页拼接可作为后续导出能力。缺少录播时可提供人工指定范围或资料推断大纲的补充路径，但需明确标注其依据。

作业生成/解答、检查和自动上传属于低优先级扩展。保留自测练习与正式作业两种概念，后续再细化检查标准和上传触发方式；它们不作为首个讲义闭环的前置条件。

## 2. Agent、Skill 与前后端职责

- Agent 是工作流中心：理解用户目标、选择 Skill、组织步骤、依据中间结果继续执行。
- Skills 描述课程同步、资料分类、转写、大纲提取、按大纲选材、讲义生成和检查等可组合流程。具体拆分可调整，不以存在几个 Skill 名称代替可执行流程。
- 应用服务提供实际工具：下载、上传接收、解析、索引、范围读取、结构化产物保存、任务状态和失败恢复。Agent 必须能调用主流程需要的这些能力。
- 前端通过独立后端 API 访问课程、课次、资料和文档，展示阶段进度、可编辑成果和来源。课程内主界面以课次列表和学习文档为中心，Agent 与当前文档保持上下文。
- 转写、OCR、文档理解、生成、Embedding 等模型计算优先使用可配置的云端 API。允许本地文件管理、音频切分和格式转换；不把本地模型安装作为默认要求。
- 用户发起一次“整理这节课”后，范围内的同步、分类、解析和生成应连续执行。只有确实缺少课程映射、材料或必要认证等信息时才中断。

## 3. 实现建议：需要补齐的数据关系

以下是承载需求的建议模型，尚未实现：

| 对象 | 必要信息与关系 |
| --- | --- |
| Course | 本地 ID、教学网稳定 ID、学期、课程名、教师；同步时更新和去重。 |
| Lesson | 所属课程、节次、日期、标题、处理阶段；关联一份或多份录播/录播区间。 |
| Asset | 课程归属、原文件、类型、教学用途（教材/补充教材/课件/录播等）、远端或上传来源、解析状态。 |
| Outline | 所属课次、主题及顺序、录播时间范围；可以查看和修订。 |
| SourceSelection | 主题对应的资产 ID、页码/块/时间范围、选材理由；支持跨资料选取和人工调整。 |
| LearningDocument | 所属课次、讲义正文、图片附件、使用的大纲与选材结果；可独立于聊天读取和编辑。 |

索引块需要能够回到原文件的具体位置。来源可在侧栏展示，正文保持可读。自动分类和关联应允许纠正；不能把“同一份文件”硬编码为“同一节课”。

## 4. 首轮核查结果

检查范围：domain/storage、pku3b adapter/service、document/recording 服务、Pi tools/skills、REST API、Vue 工作区、现有测试，以及本地 reference 源码。以下优先级针对本次产品目标。

### P0：主流程尚未成立

1. **没有课次、大纲和范围选材模型。** `packages/core/src/domain/types.ts` 定义课程、远端资源、文本块等，没有 Lesson、Outline 或 SourceSelection。`packages/core/src/agent/pi-agent-service.ts:185` 只保存按名称命名的 note；`packages/core/src/storage/course-workspace-service.ts:185` 将其放到课程级 `notes/<name>.md`。转写结束即完成任务（`packages/core/src/recordings/recording-service.ts:133`），不产生大纲或触发选材。缺少这些中间产物，无法落实先确定本节范围、再整合教材的流程。

2. **课程获取没有接到建课入口。** `apps/web/src/components/CreateCourseDialog.vue` 要求手填课程名、教师、学期和可选教学网 ID；`apps/server/src/server.ts:373` 创建本地课程。现有同步从已映射课程开始（`packages/core/src/integrations/pku3b/teaching-network-service.ts:319`）。Adapter 虽有 `course-table` 命令，但没有自动发现课程并建立/更新工作区的业务链路。

3. **拖入资料与下载后解析未接通。** 当前 Web/API 没有文件上传与拖放入口，索引接口接受的是已在服务器课程目录内的路径。远端导入在移动下载目录、标记 imported 后完成（`packages/core/src/integrations/pku3b/teaching-network-service.ts:402`），没有调用解析或索引。界面虽有“重建索引”，其扫描范围不含 `materials/original`（`packages/core/src/documents/document-service.ts:359`）。因此刚下载的课件不会自动成为讲义素材，即使重建索引也补不上这一步。

4. **Agent 工具不足以自动完成主流程。** `packages/core/src/agent/pi-agent-service.ts:23` 的工具列表没有课程发现/同步、解析、录播转写、分类、大纲保存、范围选材。`list_course_resources` 只读数据库；名为 `course-sync` 的 Skill 实际仅能查看和导入已同步资源。专用讲义会话进一步只允许读预选整份文件和保存笔记（同文件 `:269`）。需要保留课程范围约束，同时让 Agent 能在授权资料库内按大纲检索和选择具体内容。

5. **前端还未围绕学习文档组织。** `apps/web/src/components/CourseWorkspaceView.vue:594` 的 notes 页面是素材勾选表，随后打开聊天面板。没有按课次浏览讲义、打开已保存笔记、编辑正文、调整大纲和选材的文档工作区。文件落盘能力不能替代平台内持续阅读和修改。

### P1：资料质量与参考实现差距

6. **输入格式和图表保存不足。** `packages/core/src/documents/document-service.ts:184` 只接受 PDF/Markdown/TXT，无法直接处理 PPT/PPTX、DOCX 或图片。MinerU 结果只取一个 Markdown，随后删除整个临时目录（同文件 `:139`）；未复制其图片附件，Markdown 中的相对图片引用可能失效。表格行也会经段落处理合并空白。需要保存解析产物的图表、公式和原始位置，不能只保留扁平文本。

7. **资源树只有容器能力，当前数据源未提供层级。** `RemoteContentNode` 和 `buildResourceTree` 支持 `parentId`，但 `packages/core/src/integrations/pku3b/output.ts:28` 的实际解析没有填充父节点；本地 pku3b `cmd_course_content.rs` 输出平面内容列表。因此当前同步不能恢复 reference/pku3b_AI 展示的真实栏目/文件夹树，更不能把这种显示当作智能资料分类已经完成。需补充上游结构信息或明确使用平台自有分类，两者分别记录。

8. **课程自定义提示词未接入生成。** 创建课程时写入 `prompts/notes.md` 等文件，但当前 Pi loader 禁用 context files 和 prompt templates，生成路径没有读取这些课程提示词。旧 PLAN 中的课程提示词覆盖尚未落实。

### 已有可复用能力

- 前后端分离已成立：Vue/Vite、Fastify REST/SSE、共享 TypeScript core 和 CLI。
- 已有按稳定资源 ID 下载、远端资源元数据、录播清单、OTP 暂停恢复和任务状态管理。
- 已有录播下载、音频分片、云端转写、时间块 Markdown 落盘与索引。
- 已有文本索引、全文/向量检索、按课程读取、笔记和练习文件保存。
- 当前 MinerU 已通过包装 CLI 显式调用 `--engine cloud`；转写和 Embedding 也使用 HTTP Provider。旧 PLAN 的“默认本地 MinerU”描述已过时。
- 已有作业草稿、PDF 导出、审批和提交基础；未发现独立的答案检查闭环，可留到低优先级阶段处理。

## 5. reference 的实际借鉴点与边界

| 本地参考 | 已检查的实现 | 应如何使用 |
| --- | --- | --- |
| `reference/pku3b/src/cli/cmd_course_content.rs`、`cmd_course_table.rs` | 课表 raw JSON、按 `course_id:content_id` 下载内容，内容列表为平面文本。 | 延用执行器；课程发现需核对课表信息与 Blackboard ID 的映射，不能假设课表 JSON 自带教学网稳定 ID。空资料课程也必须能被发现。 |
| `reference/AutoPku/sub-skills/tasks/sync-notices.md`、`write-notes.md` | 真实获取教学网数据、按课程建目录、任务 Skill 编排、保留定义/定理/证明、生成笔记索引。 | 借鉴流程拆分和内容质量标准；其笔记按 PDF 处理，本项目需实现录播驱动的课次组织与跨资料选材。 |
| `reference/pku3b_AI/pku3b_ai/mcp_pku3b_server.py`、`doc/mcp_tool_summary.md` | 课程树、节点检索、正文与附件工具、Handle/Detail 思路。实际启动代码会立即加载全部课程。 | 借鉴对象与工具粒度；实现按需加载和稳定 ID，不复制按序号定位或启动时全量加载的行为。 |

以上参考能支撑课程获取和 Agent 工作流设计，但在本轮检查的这些路径中，没有可直接接入的“录播大纲 → 教材范围选取 → 每课讲义”完整实现。

## 6. 实施顺序与验收

1. 建立课次、资料身份、大纲、选材和学习文档的数据关系，以及对应存储/API；明确现有课程、笔记如何兼容。
2. 接通 pku3b 课程发现/映射、资料上传和下载后解析入库；补齐教材、课件格式和图片资产保留。
3. 补齐 Agent 工具及 Skills：录播转写 → 大纲 → 按主题检索和范围读取 → 讲义生成。长任务展示阶段状态，失败能够从可用中间产物继续。
4. 改造课程前端：课次列表、文档阅读/编辑、资料拖入、大纲及来源调整、Agent 上下文联动。
5. 用真实课程完成主流程验收后，再完善练习、作业检查和自动上传；树洞等已有扩展暂不占用主线优先级。

首个验收场景：从教学网获取一门课，加入一本主教材、一本补充教材和课件，选择某节录播，执行一次整理指令。系统自动生成可查看的大纲，记录每个主题使用的页/段/时间范围，保存含必要图表的本节讲义，并在该课次下直接打开阅读和修改。

还需检查：同一教材跨课次使用不重复导入；同名不同学期课程不混淆；只讲半章时不整章灌入；无匹配资料时明确缺失；用户修改范围后生成采用新范围；解析失败不误报可用；刷新页面后仍可读取已生成文档。自动同步不得覆盖用户编辑的文档。
